# Live Church Translation

[English](README.md) | 简体中文

Live Church Translation 是面向教会现场的 macOS 本地听抄与翻译工具。它支持普通话到英语、
英语到简体中文两种方向，保存完整录音和听抄稿，并可把只读实时页面分享给同一局域网内已配对的
手机、平板和电脑。

应用面向 Apple Silicon（arm64）和 macOS 15 或更高版本。正式安装包内置固定版本并校验过的
Qwen3-ASR、Hy-MT2、sherpa-onnx 与 llama.cpp 运行组件；使用者无需安装 Python、Node、Ollama、
LocalVocal 或其他运行环境。

## 主要功能

- 从所选麦克风采集音频，以 VAD 形成适合阅读的语句片段。
- 会话开始前选择“普通话 → 英语”或“英语 → 简体中文”，方向会随听抄稿和共享页面保存。
- 在本机保存可恢复的完整 CAF 录音、JSONL 原始记录和可阅读的 Markdown 听抄稿。
- 在资料库中搜索、播放、重新听抄或删除会议记录，并可导入 WAV、AIFF、MP3、AAC/M4A 和 CAF。
- 使用可编辑的属灵术语表；保留识别原文、审慎修正、译文及其审计信息。
- 远端听众只能阅读，不能开始或停止录音，也不能更改麦克风、模型、术语表、设置或历史记录。

自动校验只能发现数字、否定、经文格式、术语、异常长度或模型说明等特定问题，不能证明译文在
神学或语言上绝对正确。正式发布仍需要独立的双语人工审阅。

## 安静而明确的过程反馈

应用和共享页面使用小型、持续、不过度醒目的状态提示，而不是突然弹出一句话。Mac 处理阶段明确
分为“准备中”“正在聆听”“正在识别”“正在翻译”“正在完成”和“未完成”；中文共享页对应为
“正在准备”至“已暂停”，英文共享页对应 Preparing 至 Paused。共享连接另行显示“正在连接”、
“已连接”或“正在重新连接”（英文为 Connecting、Connected、Reconnecting）。短暂阶段可使用
克制的加载指示，录音时长与处理阶段分开显示，避免“正在录音”遮住实际进度。

每段内容默认显示时间戳，Mac 与浏览器都可独立隐藏。隐藏只改变界面，录音偏移仍保留在 JSONL、
Markdown 和资料库记录中。

上述交互改动及下述局域网崩溃修复，必须在最终提交上完成自动化、完整 Xcode 和真实设备验证后，
才能作为发布证据。

## 录音与故障恢复

完整录音在模型推理前开始保存。每个 VAD 片段也会在识别前写入恢复区，只有译文已持久化后才标记
完成；意外退出后会按会话和顺序重放。损坏、截断或超限文件会被隔离并明确提示，不会被静默丢弃。
所有应用数据位于 `~/Library/Application Support/LiveChurchTranslation/`。

## 局域网共享与隐私

共享默认关闭。开启后，邀请链接使用高熵凭证和仅内存保存的会话授权；停止共享或退出应用会撤销
访问。页面不依赖 CDN、分析脚本或第三方资源。当前传输为局域网 HTTP/WebSocket，不提供 TLS
机密性，因此只能在可信的教会或家庭网络使用，不应端口转发，也不应在不可信公共 Wi‑Fi 上开启。

2026-08-24 的两份 macOS 15.5 实机报告显示，工程安装包在 Safari 建立共享连接后会陷入
`WebSocketFrameCodec.parseClientFrame(_:)` 的越界陷阱。这推翻了此前仅基于 loopback 的“共享
通过”结论。根因是帧解析器把 `Data` 索引错误地假定为从零开始；修复后的发布门槛包括跨多次接收
拆分的单帧、同次接收的合并帧、非零起始索引、心跳、重连、停止/重启共享的回归测试，以及
iPhone、iPad 和 Mac Safari 重复连接时应用不退出。修复代码已于 2026-08-24 通过完整命令行门禁；
完整 Xcode 与上述真机 Safari 验收仍待完成，不得仅凭自动化结果发布。

## 使用步骤

1. 启动应用，等待内置模型校验和加载；按提示允许麦克风权限。
2. 选择翻译方向、音频输入和所需术语表。
3. 点击“开始”，确认现场人员已知晓录音；完整录音会先于模型准备保存。
4. 通过安静的阶段提示确认系统仍在工作，阅读译文；需要时隐藏时间戳或返回最新内容。
5. 点击“停止”，等待剩余语音处理完毕，再到“资料库”查看录音与听抄稿。
6. 如需共享，在可信局域网内开启“听众共享”并让听众扫码；使用完毕后停止共享。
